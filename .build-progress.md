## Decisions and pins
- `cmaboss==1.0.0b34`, an exact pin (beta). BSD-3-Clause: maboss-bkmc/MaBoSS's own workflow builds and uploads it from
  `engine/python`, and the wheel metadata omits the licence. It imports numpy without declaring it.
- Runtime dependencies: process-bigraph>=1.9.1, bigraph-schema>=1.8.1, cmaboss, numpy. The dashboard stack is the
  `dashboard` extra; `dev` includes it (workspace-ci installs `.[dev]`); the Dockerfile and Singularity.def install it.
- Name: the template derives the package as `viva_<name>`, so `--name viva-maboss` gave `viva_viva_maboss`;
  re-scaffolded with `--name maboss` and renamed the distribution to `viva-maboss` (`maboss` is a different PyPI
  package).

## cmaboss facts (verified 2026-11-03)
- `MaBoSSSim(bnd_path, cfg_path)` takes file paths. `$parameters` go in the `.cfg` (a `$` line in the `.bnd` is a
  syntax error). `verbose` is not a valid config key.
- `update_parameters({...})` is accepted and has no effect on the result, so parameters are written into each `.cfg`.
- `<node>.istate = 0|1` in the `.cfg` sets the start; `network.set_istate(node, [p0, p1])` takes per-node
  distributions only; there is no joint-state setter.
- Results are window averages: with max_time 2 and time_tick 0.5, the "last" probtraj is at t = 1.5, for [1.5, 2.0).
  Verified against the analytic window average (0.62277 against 0.62277; the instant value is 0.63212).
- The same seed reproduces exactly.

## Workarounds and gotchas
- process-bigraph 1.9.1 treats a zero config value as unset (fills the default), so validation tests use -1.
- `local:viva_maboss.processes.MaBoSSProcess` resolves only from a regular (non-editable) install: discovery reads
  installed distributions, and a hatchling editable install is not mapped. The module-address test skips under
  editable installs and passes from the built wheel (verified at process-bigraph 1.9.1 / bigraph-schema 1.8.1).

## Adversarial review (2026-11-03, at 8f35bbf) and fixes
- BLOCKER, fixed: a negative rate killed the interpreter (SIGBUS, exit 138, reproduced). Rates are refused unless
  finite and non-negative.
- My claim "exact in distribution" was false. The carried state lags by half a window. Corrected in the docs; measured.
- Windows misaligned when the interval was not a whole number of time_ticks. Replaced time_tick with
  windows_per_interval.
- Stores drifted (deltas were taken against instance memory). Deltas are now taken against the input stores, and
  node_probabilities is an input.
- Seeds: seed + index made streams overlap, and the index was lost on restart. SeedSequence([seed, steps]) with a
  `steps` store fixes both.
- Testing the coupling with single-trajectory replicates found that MaBoSS mishandles seed_pseudorandom >= 2^31 (0.64
  against 0.26). The engine seed is masked to 31 bits.
- 64-node cap: the smallest cmaboss_<n>n build that fits is used.
- The oracle could not separate window from instant at a 0.1 tick. Added a wide-window test.
- Results: dev env 30 passed, 2 skipped; pinned 1.9.1/1.8.1 wheel 29 passed (the module-address test included).
- Not done: CI still installs editable, so it never exercises the compose-api address (the template's workflow); the
  compose-api runner case is the gate.
